# TALTOへの原稿移行ガイド

## 結論

TALTOの現行エディターには、MarkdownまたはHTMLファイルを直接読み込む機能はありません。Markdownをそのまま貼ると、`#` や `**` は書式ではなく文字として入ります。

一方、クリップボードにHTMLが含まれている場合は、TALTOがHTMLをLexicalノードへ変換します。このため、安全性と作業量のバランスがよい方法は次の流れです。

1. 移行元の原稿を用意する
2. `TaltoConv.html` でTALTO向けHTMLへ変換する
3. 本文を「リッチテキストでコピー」してTALTOの本文欄へ貼る
4. 保存済み表示を確認してから次の冊子へ進む
5. 画像はプレースホルダーの位置へ手動で挿入する

補助ツールはローカルだけで動作し、原稿やログイン情報を外部へ送信しません。TALTOの非公開APIを直接書き換える処理もありません。

## 補助ツールの起動

通常は `TaltoConv.html` をダブルクリックしてブラウザで開けます。

ブラウザの制限でローカルファイルのコピー機能が動かない場合は、このフォルダで次を実行し、表示されたURLを開きます。

```powershell
node tools/serve.mjs
```

## 対応表

| 原稿 | TALTOへ渡す形 | 結果 |
|---|---|---|
| `#`／`##`／`###` | `<h1>`／`<h2>`／`<h3>` | 見出し1〜3 |
| 文字の次の行に `===`／`---`（Setext形式） | `<h1>`／`<h2>` | 見出し1〜2 |
| 通常段落 | `<p>` | 本文 |
| `>` | `<blockquote>` | 注釈 |
| `**太字**` | `<strong>` | 太字 |
| `*斜体*` | 通常文字 | 文中の斜体装飾を除去。`_斜体_` は単語内（`snake_case`）では書式にしない |
| 行全体が `*斜体*`／`_斜体_` | `<blockquote>` | 「Obsidianの斜体を注釈にする」が有効なら注釈 |
| `~~取消~~` | 通常文字 | 取消線装飾を除去 |
| インラインコード | 通常文字 | コード装飾を除去 |
| HTMLの `<u>` | `<u>` | 下線 |
| 改行 | `<br>` | ブロック内改行 |
| H4〜H6 | 太字の通常段落 | 階層を失わず視覚的に区別 |
| 箇条書き／番号付きリスト | `・`／`1.` 付き段落 | 記号を残して構造を単純化 |
| 表 | `｜` 区切りの段落 | セル内容を残して構造を単純化 |
| `---`／`***`／`___`、HTMLの `<hr>` | 横線文字または削除 | 画面の設定で選択。段落の直後の `---` はSetext見出し2 |
| リンク | `表示名（URL）` | URLを文字として保持 |
| 画像 | `【画像：説明｜参照先】` | 挿入位置を保持し、あとで手動挿入 |

## 安全な手作業フロー

### 1. 原稿を整える

- 原則として「1ファイル＝1冊子」にする
- 先頭行を見出しにする場合は `# 見出し` のように記載する。ファイル名は本文へ追加されない
- 本文の見出しは `##` と `###` を中心にする
- 画像は `![説明](images/map.png)` のように記載しておく
- 移行前のMD／HTML原稿は変更せず、コピーを使う

### 2. 補助ツールで変換する

- 複数ファイルをまとめて選択できる
- 入力方法は「原稿を貼り付ける」「ファイルを読み込む」「フォルダを読み込む」のいずれかを選ぶ。複数の入力方法に内容があっても、選択中の一つだけを変換する
- ファイル／フォルダ読み込みの対応拡張子は `.md`、`.markdown`、`.html`、`.htm`、`.txt`。フォルダでは対応ファイルだけを相対パス順で取り込み、画像とその他のファイルは読み込まず除外件数を表示する
- 通常はファイル読み込みを1ファイル10MBまで、フォルダ読み込みを対象原稿の合計100MBまでに制限する。超過時は読み込みを停止し、設定の「変換オプション」から「ファイル容量の制限を解除」をONにした場合だけ再選択して読み込める。解除中は動作が重くなったり画面が固まったりする可能性がある
- ファイルは複数回に分けて追加しても、それまでの一覧を保持する。複数ファイルは一覧の上から下へ1つの原稿として結合し、行のドラッグ＆ドロップまたは上下ボタンで結合順を変更できる。各行の×ボタンで一覧から外しても、元ファイル自体は変更しない
- ObsidianのYAMLプロパティ（先頭の `---` 〜 `---`）は各ファイルの先頭でだけ除外する。原稿の途中にある `---` で挟まれた行は本文として残す
- ファイル内容の形式は拡張子から自動判定しない。結合した原稿全体を、画面で選択したプレーンテキスト、CommonMark、GFM、Obsidian Markdown、pixiv小説形式、HTMLのいずれか1種類として読み取る
- HTML拡張子とそれ以外が混在する場合は変換を停止する。全ファイルの内容と選択形式を確認した場合だけ強制実行し、表示崩れがないか確認する
- 先頭の見出しは初期状態では本文に残る。不要な場合だけ「先頭の見出しを本文から除外」を有効にする。ヘルパーは冊子タイトル／ファイル名を本文の先頭へ追加しない
- 空行は「一括でそろえる」「種類別にカスタム」を切り替えて設定する。一括ではすべてに共通の前後の空行数、カスタムでは見出し1・2・3・注釈・本文の5種類ごとに前後0〜10行を指定できる
- 隣接するブロックの「後」と「前」は大きい方を採用する（見出しの後2行、本文の前1行なら間は2行）。原稿の先頭と末尾の空行は初期状態では入らず、必要な場合だけ個別に有効化する。本文は段落単位で、同一段落内の改行には追加しない。リスト・表・H4〜H6など通常段落に変換される要素も本文の設定を使う
- 見出し1〜3が連続する箇所は「見出しが連続するときの空行」を使う。この値は両見出しの通常の前後空行や元HTMLの空段落より優先され、足し算や重複はしない
- 空行はTALTOの空段落1つを1行として出力する。空段落の中に改行要素を重ねないため、指定数が二重にならない
- カスタムへ初めて切り替えたときは一括の値を引き継ぐ。その後はモードを切り替えても種類別の値を保持する。「一括の値を適用」で再びそろえられる。設定値と入力方法は端末内に保存されるが、原稿本文と読み込んだファイルは保存されない。設定はデフォルトへ戻すか、テキスト設定ファイルとして保存・読込できる。読み込んだ設定は種類別カスタムとして適用する
- 「見出しをまとめて太字に」で見出し1・2・3を個別に選択できる。選んだ種類の見出し全体に太字を適用する。未選択の種類は原稿内の太字指定を保つ
- 入力や設定変更はプレビューに自動反映される。PCは原稿・形式・設定とプレビューを横並びに表示し、スマホは「原稿」「形式」「設定」「確認」の4画面を切り替えて操作する
- プレビューの「PC / スマホ」は表示幅の確認用で、書き出す内容は同じ。TALTOの画面を完全再現したものではないため、貼り付け後に最終確認する
- Obsidianで行全体を斜体にした箇所を注釈として使っている場合は、「行全体が斜体をTALTOの注釈にする」を有効にする。文中の斜体と打消しは通常文字へ簡略化する
- MDの区切り線が不要なら、「Markdownの区切り線を削除する」を有効にする。無効の場合は横線文字として残る
- 警告欄で、画像・表・リストなど変換された要素を確認する
- 原稿内の画像参照は「【画像：説明｜リンク】」として残る。画像ファイル自体は読み込まれないため、リンクを目印にTALTOで手動挿入する
- コピー形式はリッチテキスト・書式なしテキスト・HTMLから選ぶ

スマホでは、`TaltoConv.html` と `src` フォルダの位置関係を保って使うか、スマホから到達できる配信元が必要です。PCで起動した `http://127.0.0.1:8765/` は、そのPC専用のアドレスです。このツールは外部公開やネットワーク公開を行いません。

### 3. TALTOへ貼り付ける

- 新規冊子を追加するか、移行先の空冊子を選ぶ
- 「リッチテキストをコピー」で本文を貼る
- 既存本文を置き換える場合だけ、本文欄をクリックしてから `Ctrl+A` で本文を選択する。ページ全体が選択されていないことを確認してから貼る
- 貼り付け後、左下の最終保存時刻と保存済みアイコンを確認する
- 保存完了前に別冊子へ切り替えたり、連続して大量操作したりしない

### 4. 画像・添付ファイルを処理する

- 本文画像はJPEGまたはPNGのみ
- 本文画像は1枚2MiB以下
- `【画像：…】` の段落を目印に、画像ボタンまたはドラッグ＆ドロップで挿入する
- 画像が表示されたことを確認後、プレースホルダーを削除する
- 配布用の添付ファイルは本文画像とは別機能で、1ファイル50MiB以下

### 5. 最終確認

- TALTOのプレビューで各冊子を開く
- 冊子順、H1〜H3、注釈、太字、改行を確認する
- リスト・表・リンクが読みやすい文字列として残っているか確認する
- 画像の位置と大小を確認する
- 保存エラーや「他のブラウザでの編集」警告が出た場合は、それ以上貼り付けず、ページを再読み込みして対象冊子だけやり直す

## 解析根拠

- TALTOが登録している本文ノードは `HeadingNode`、`QuoteNode`、`ImageNode`、`DivParagraphNode`。リスト・表・リンク専用ノードは登録されていない：`app/pages/EditorLexical/components/Editor/Editor.tsx`
- リッチテキストの貼り付けは、Lexical形式、`text/html`、`text/plain` の順に処理される：`vendor/node_modules/@lexical/clipboard/LexicalClipboard.prod.js`
- Markdownショートカット／Markdownインポート用プラグインはアプリ本体に登録されていない
- 見出しと引用はHTMLの `h1`〜`h6`、`blockquote` から変換される：`vendor/node_modules/@lexical/rich-text/LexicalRichText.prod.js`
- TALTO向けにこのヘルパーが保持する文字装飾は、画面で利用できる太字と下線に限定する
- HTML内の画像は、現在のTALTOプロジェクト用Firebase Storage URLだけが画像ノードとして認められる：`app/pages/EditorLexical/nodes/ImageNode/ImageNode.tsx`
- ローカル画像のアップロードはJPEG／PNG、2MiB以下：`app/pages/EditorLexical/nodes/ImageNode/ImagesPlugin.tsx`
- 自動保存は500msのデバウンスとシーケンス番号による競合検出を使用する：`app/pages/EditorLexical/components/AutoSavePlugin/AutoSavePlugin.tsx`
- 添付ファイルは50MiB以下：`app/pages/Editor/EditorMainContainer/EditorMainAttachment/EditorAttachmentDropArea/EditorAttachmentDropArea.tsx`

## 直接API書き込みを採用しない理由

ドラフトAPIの形式自体は復元できていますが、直接書き込みには認証トークン、現在のシーケンス番号、Lexical JSONの完全な整合性が必要です。競合時はHTTP 409になり、誤ったデータを送ると冊子全体へ影響します。今回の目的である「安全・低工数・手作業で確認可能」には、TALTO自身の貼り付け変換と自動保存を使う方が適しています。

将来TALTO側の実装が更新された場合は、少量のテスト原稿で変換結果を確認してから本番原稿を移してください。
